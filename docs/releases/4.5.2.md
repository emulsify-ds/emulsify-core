# Emulsify Core 4.5.2

Draft patch release prepared from the published `v4.5.1` baseline for review.

## Build Output Fix

Consumer `npm run build` commands using Core's Vite configuration now print the
Emulsify wordmark, installed Core version, project details, input roots, output
file counts and sizes, and build completion summary already available during
`npm run develop`.

Production builds keep Vite's normal per-file output table. Their completion
line reports the elapsed build time. Watch builds also identify the watched
source directory. Existing detailed verbosity controls apply to the production
summary.

Standalone static Storybook builds use their compact diagnostics, allowing a
combined Vite and Storybook build to print one Emulsify banner.

## Dependency Maintenance

Raise 31 dependency minimums and regenerate the lockfile through npm. Updates
include Glob 14.0.3, the aligned Storybook 10.6.5 family, Jest 30.5.2, Vite
8.3.5, Sass 1.107.1 and Puppeteer 25.16.0. The existing Glob APIs need no Core
configuration or consumer migration.

Keep the Babel compiler on 7, ESLint on 9 and Stylelint on 17 where published
plugin, peer or engine requirements block the next major. Keep the standalone
Babel parser on the latest 7.x version, 7.29.12, at the maintainer's request.
The [dependency review](../dependency-review-4.5.2.md) lists every declared
requirement, selected and latest stable versions, and the upstream evidence for
these exceptions. No overrides or third-party patches were introduced.

## Compatibility And Upgrade

Core continues to support Node.js 24.13.0 or newer. Existing consumer scripts
receive this reporting fix by updating Core and the project lockfile.

After 4.5.2 is published, run these commands in the project or theme that depends
on Core.

```sh
npm install @emulsify/core@^4.5.2
npm ci
npm run build
```

Use `npm install --save-dev @emulsify/core@^4.5.2` for a project that already lists
Core in `devDependencies`. Commit the resulting package and lockfile updates
together.

The intended publishing branch is `main`, using npm's `latest` channel.

Linux ARM64 validation in a disposable Node.js 24.16.0 container completed
lifecycle-enabled `npm ci`, lint, all 118 suites (1,554 tests and 12 snapshots),
and an installed tarball's production consumer build.

The conventional `fix(reporter)` commit selects a patch from 4.5.1 to **4.5.2**,
through **main / latest**. The aggregate `release:verify` passed every runtime and
package check before committing; its final history-based analysis is checked
separately after the release-producing commit exists. CI and the authenticated

was supplied directly during release preparation and has no linked issue.
