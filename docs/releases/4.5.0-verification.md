## Release Calculation And Commit Scope

The existing `version:develop` script updated only the three package version
fields from 4.4.0 to 4.5.0. That metadata adjustment has its own `chore`
commit so it agrees with the release verifier without adding a release
trigger. The sole new `feat` commit is
`f61b5d7 feat(a11y): add an optional WCAG 2.2 rule preset`.

The verification command was:

```sh
RELEASE_FROM=origin/main RELEASE_TO=HEAD \
  RELEASE_SQUASH_MESSAGE='feat(release): prepare 4.5.0' \
  npm run release:analyze
```

`RELEASE_FROM` is the main-branch release base used to discover the latest
published tag, not simply the first local sprint commit. Main reaches
`v4.4.0`; the pre-sprint develop commit `8eb51f9` reaches only `v4.3.2` in
its ancestry. Using that develop commit as the base incorrectly selected
the older tag and failed the package-version guard. Using the publication
base analyzes the intended `v4.4.0..HEAD` range, containing the sprint and
the preserved pre-existing audit correction. No analyzer exception or
historical release rule was changed.

## Open Audit Findings Kept Outside This Sprint

Independent review of pre-existing commit `8eb51f9` found the following P2
issues. The maintainer chose to record them and retain the requested scope;
no audit classifier behavior was changed by this sprint.

1. **A shared helper can hide a legacy render path.** In
   [`story-render-paths.js`](../../scripts/audit/lib/story-render-paths.js),
   helper declarations referenced by `renderTwig` are marked modern
   globally. Given `const Template = args => cardTwig(args)`, a modern
   `render: renderTwig(Template)` export causes a separate
   `Legacy = Template.bind({})` export to produce `shouldUpgrade: false`.
   Removing the modern export restores the expected warning. A follow-up
   should classify each render path independently and cover direct, bound,
   and object-render reuse of the same helper.
2. **Capitalization is mistaken for CSF story inclusion.** The same
   analyzer's uppercase-only named-export filter misses the valid
   `export const primary = args => cardTwig(args)` story. Renaming it to
   `Primary` restores the warning. It also does not implement statically
   readable `includeStories`/`excludeStories` filters; an explicitly
   excluded uppercase helper is still reported. That exclusion limitation
   already predates `8eb51f9`. A follow-up should use
   [CSF's export rules](https://storybook.js.org/docs/api/csf#named-story-exports)
   and cover lowercase exports plus array/regex filters.

The first two false-negative cases reproduced as warnings on `8eb51f9`'s
parent and as missed findings on the pre-sprint/current code. The existing
four targeted suites (28 tests) pass but do not cover those cases. These
findings are not approval of the pre-existing change and remain visible
despite green release checks.
