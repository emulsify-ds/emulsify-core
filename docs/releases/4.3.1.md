# Emulsify Core 4.3.1

Emulsify Core 4.3.1 is a patch release that finishes the develop reporter
introduced in 4.3.0. It changes no public API, no output paths, and nothing a
platform ships. Every change is confined to what `npm run develop` prints.

For related documentation, see:

- [Develop Reporter](../develop-reporter.md)
- [Project Structure And Output](../project-structure.md)
- [Migration To 4.x](../migration-4x.md)

## Why This Is A Patch

4.3.0 shipped the reporter: it replaced Sass's per-occurrence deprecation blocks
and Rolldown's aggregate failure dumps with a banner, one summary per build
cycle, and one line per rebuild.

What it did not do was stop the _other_ participants in `develop` from talking. A
representative run on a real consumer theme emitted around 112 lines before the
first rebuild, of which the reporter's own summary was fewer than ten — so the
summary it existed to produce scrolled away before it could be read. Two of the
three changes here repair output that arrived garbled or duplicated; the third
reshapes a summary the same reporter already printed.

Those commits were authored as `feat` before that framing settled.
`config/release-analysis.cjs` classifies them as `patch`, alongside the existing
precedent there for the 4.x major.

## Where The Output Came From

| Lines | Producer                                                      | Channel                   |
| ----- | ------------------------------------------------------------- | ------------------------- |
| 7     | npm script echo, nested through `concurrently`                | consumer's own scripts    |
| 5     | Vite JS build chatter                                         | `config.logger.info`      |
| ~4    | Rolldown progress (`transforming (N)`, `modules transformed`) | Rust → stdout direct      |
| ~78   | Rolldown asset table + `computing gzip size...`               | Rust → `logInfo` callback |
| 8     | Storybook's boxed `Storybook ready!` banner                   | `@clack/prompts` box      |
| ~10   | Emulsify reporter                                             | direct stdout             |

### Quieting Vite And Rolldown

`config/vite/vite.config.js` supplied a `customLogger`, and its comment asserted
that `config.logLevel` "cannot do this job" because Vite ignores the level when a
custom logger is present. That is true of `createLogger`, and false of the thing
that mattered.

Vite's build reporter reads `config.logLevel` directly and independently of the
logger, passing a `logInfo` callback only when the level admits info:

```js
const shouldLogInfo = LogLevels[config.logLevel || 'info'] >= LogLevels.info;
// ...
logInfo: shouldLogInfo ? (msg) => env.logger.info(msg) : void 0,
```

That flag crosses into Rolldown's native plugin, whose Rust `register_hook_usage`
registers its Transform, BuildStart, BuildEnd, RenderChunk, WriteBundle, and
GenerateBundle hooks only when the callback exists. So raising the level does not
merely hide the report — Rolldown stops instrumenting transforms and computing
gzip sizes at all, which makes every rebuild cheaper.

It also removes the `transforming (N)` progress line. Rolldown writes that from
Rust with a `\x1b[2K\r` prefix and no trailing newline, and that carriage return
is what produced the garbled collisions with Storybook's output when
`concurrently` merged both streams onto one pipe. Nothing on the JavaScript side
could intercept it.

Both switches are now set, because neither substitutes for the other:
`createLogger` returns a supplied `customLogger` verbatim and never consults the
level, while the build reporter consults the level and never consults the logger.

`build.reportCompressedSize` is deliberately untouched. It suppresses only the
gzip column, and the table it belongs to is already gone.

### Folding In Storybook

Storybook's ready box is drawn in its own visual language, which made one command
look like two. `.storybook/ready-reporter.js` intercepts `logger.logBox` from
`storybook/internal/node-logger` and re-renders the payload as the reporter's
panel.

Storybook has a switch for this — `outputStartupInformation` is called behind
`options.quiet` — and it was deliberately not used, for two reasons. The
`storybook` script lives in each consuming project's `package.json`, so `--quiet`
would make a cosmetic improvement conditional on every consumer editing a script.
And the box carries information available nowhere else: consumers run
`storybook dev --ci`, and `--ci` makes Storybook fall forward to the next free
port without prompting, so the resolved port appears only in the box. Parsing it
is what makes the port drift warning possible.

Every failure path is non-fatal. An unavailable import, an unparseable box, or a
write failure all fall through to Storybook's own output, so the worst outcome is
the box that printed before. Only the ready box is affected; migration notices and
error summaries pass through untouched.

### The Summary Itself

The summary reported that a build succeeded and what was wrong with it, but
nothing about what it read or wrote. It now opens with an aligned facts block
carrying the platform, one row per source root, and the output tally.

The input rows are the substance of the change. A total entry count cannot
distinguish a healthy project from one whose second source root was never
discovered — thirty-nine entries looks fine either way. Each root is now named
with what it contributed, and a root that matched nothing is highlighted rather
than hidden, because that row is usually the misconfiguration.

Global roots additionally break out the conventional global-asset directories
inside them: `foundation/`, `base/`, and `global/`. A global root is the source
directory itself, so it would otherwise report one opaque total for everything
outside the component roots. This is a reporting distinction only — the build
already emitted each of those directories to `dist/global/<name>/`, and nothing
about that changed.

The output row recovers the three facts worth keeping from the discarded asset
table: how many files landed, their combined size, and the largest one. Sizes are
computed from the emitted content in `writeBundle` rather than by reading `dist/`
back, so this adds no I/O.

`renderBanner` gave up the platform and entry count to make this possible. It
fires at `configResolved`, before the build, so anything it said about `dist/`
would be a guess.

Problems are now grouped under two labelled dividers. Sass deprecations are
inherited debt on almost every project and outnumber real breakages by two orders
of magnitude, so they sit below `pre-existing debt` and stop competing for
attention with the broken asset URLs from the edit you just made. A divider is
drawn only when its section has content.

## Consumer `develop` Script

`concurrently` spawns each task as its own `npm run`, and npm echoes the script it
is about to execute, so a develop session opened with several lines of script echo
before either tool had said anything. The recommended script in
[Migration To 4.x](../migration-4x.md) now runs the nested invocations with
`--silent`.

This is cosmetic and optional. Existing consumer scripts keep working; they are
just noisier.

## Verbosity Controls

| Variable                | Effect                                              |
| ----------------------- | --------------------------------------------------- |
| `EMULSIFY_VERBOSE=1`    | Restores Vite's and Rolldown's raw output in full.  |
| `EMULSIFY_NO_UNICODE=1` | Drops the wordmark, panel rules, and section rules. |
| `NO_COLOR=1`            | Disables color, per the no-color.org convention.    |
| `FORCE_COLOR=1`         | Enables color even when the stream is not a TTY.    |

## Scope Limits

The reporter takes over output only for `vite build --watch`, the watcher
`npm run develop` starts. One-shot `npm run build`, `storybook build`, and every
release fixture verification keep their previous output byte for byte.

`config/vite/plugins/reporter/diagnostics.js` also gained the missing
`syntaxErrors` field in its documented `snapshot()` shape — a JSDoc correction,
not a behavior change.

## Migration Actions For Existing Projects

None required. Optionally, adopt the quieter `develop` script from
[Migration To 4.x](../migration-4x.md).

## Release Verification

Run `npm run lint`, the full Jest suite, and `npm run release:analyze` on the
Node.js version pinned in `.nvmrc`.

Two behaviors cannot be covered by unit tests and are worth checking by hand in a
real consumer theme:

- No `\x1b[2K\r` fragments survive under `concurrently`.
- A stale Storybook holding the requested port produces the port drift warning
  rather than a silent fall-forward.
