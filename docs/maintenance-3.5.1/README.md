## Resolver evidence

The historical consumer lock was generated by npm, without overrides, direct
resolver pins, or manual lock changes:

```sh
npm install @emulsify/core@3.5.0 --package-lock-only --before=2026-04-13T00:00:00.000Z
```

It resolves `Core 3.5.0 → Jest 30.3.0 → @jest/core 30.3.0 → jest-resolve 30.3.0
→ unrs-resolver 1.11.1 → napi-postinstall 0.3.4`.

Fresh installation of the reviewed tarball and an upgrade of that historical
lock both resolve:

```text
@emulsify/core@3.5.1
└─ jest@30.5.2
   └─ @jest/core@30.5.2
      └─ jest-resolve@30.5.1
         └─ unrs-resolver@1.12.2
            └─ napi-postinstall@0.3.7
```

Core requires `jest` and `jest-environment-jsdom ^30.5.2`. Jest requires its
matching `@jest/core`, which requires `jest-resolve 30.5.1`; that resolver
requires `unrs-resolver ^1.12.1`. Thus `1.11.1` cannot satisfy Core's resolver
chain even when it remains elsewhere in a consumer's dependency tree. These
constraints are in the published package manifests, rather than Core's lockfile
or an override.

The focused permission fixture installs official packages, removes executable
bits only from its own helper CLI, and executes the upstream lifecycle scripts.
`1.11.1` fails with Permission denied: status 126 on macOS/bash and 127 with
Linux's default dash shell. A separate bash check reproduces status 126 on both
systems. `1.12.1` and `1.12.2` succeed through `node postinstall.js` and the helper's
JavaScript API while the helper CLI remains non-executable. See
[macOS](resolver-permission-macos.json) and
[Linux](resolver-permission-linux.json).

## Warnings and limitations

- The final repository audit reports 33 affected packages, including 3 critical.
  Fresh consumers report 32; the historical upgraded lock retains additional
  compatible transitive versions and reports 38. These are not all independent
  advisories. Exact owners, upstream constraints, remaining deprecations, and
  optional consumer refresh commands are in the
  [audit and deprecation report](../audit-deprecations-3.5.1.md).
- Three npm deprecations remain: `token-transformer`, Jest/jsdom's
  `whatwg-encoding`, and Jest coverage's `glob 10`. Current supported upstream
  integrations do not provide compatible replacements. No override, permission
  repair, lifecycle bypass, warning suppression, or disabled coverage was used.
- On macOS, optional `fsevents@2.3.3` fails a native build. Its owner is
  Storybook's `fork-ts-checker-webpack-plugin → chokidar` integration. npm omits
  the optional binding and installations/builds succeed. Linux does not install
  this macOS-only package.
- npm 11.19 prints advisory `allowScripts` warnings. Its default policy still
  executes lifecycle scripts; successful resolver, esbuild, and Puppeteer script
  execution is recorded in the logs. No lifecycle scripts were disabled.
- Static builds retain upstream Sass legacy API / `@import` warnings, Storybook
  child-process deprecation warnings, and asset-size warnings. Keeping Sass's
  legacy importer interface avoids a consumer migration in this patch.
- The GitHub macOS/Linux matrix is configured but has not run: nothing was
  pushed. The nonpublishing release analysis passes for a prospective `fix`
  commit, calculating `3.5.1` and asserting `legacy-3`. A full semantic-release
  remote dry run, authentication, and final merge-commit analysis remain release
  checks after review. See [release notes and channel](../release-3.5.1.md).
